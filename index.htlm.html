Arquitectura técnica

Backend · Supabase

Supabase definido como backend oficial La interfaz mantiene el prototipo local mientras se prepara la conexión real.
Plan v1.0

Database

Persistencia central para usuarios, perfiles, eventos, tickets, órdenes, pagos, stock y finanzas.

Auth

Autenticación y sesiones para separar asistentes, artistas, managers, productoras, venues, RRPP y staff.

Storage

Fotos, logos, preskits, riders, videos y archivos de portfolio vinculados a perfiles y eventos.

RLS

Reglas de seguridad para que cada usuario pueda acceder únicamente a los datos que le corresponden.

API

La aplicación utilizará la capa de datos para crear, consultar y actualizar recursos sin depender de localStorage.

Realtime

Preparado para futuras actualizaciones en tiempo real de ventas, accesos, stock y paneles operativos.

Rol actual

Seguridad prevista

Reglas conceptuales que vamos a convertir en políticas RLS al conectar Supabase.

IdentidadUn usuario tendrá una cuenta y un perfil asociado.
RolesLos permisos se determinan por rol y contexto de organización.
ProductorasPodrán administrar solamente sus propios eventos, finanzas, stock y staff.
StaffAcceso limitado a operaciones asignadas, especialmente validación de entradas.
AdminAcceso global para gestión de la plataforma y moderación.
Datos sensiblesPagos y datos privados no deben exponerse al cliente sin autorización.
